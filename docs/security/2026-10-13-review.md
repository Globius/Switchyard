# Security review, 2026-10-13

Scope: `origin/main` at `6f2fc5b` (controller, agent, posture agent, OpenTofu provider, `deploy/`, Helm chart, CI). This is the third
review. It builds on [the backend review](backend-review.md) (2026-10-11) and [the UI review](ui-review.md), and concentrates on code
and configuration added since: the Grafana proxy, packet capture, device posture and device certificates, Kubernetes and DNS
connectors, the production compose files, the Helm chart and CI. Method: reading against ADR 0030 and CLAUDE.md, a route inventory
against the permission matrix test, targeted searches (SQL, subprocess, deserialisation, outbound URLs, logging), and these scanners:
`pip-audit` (controller lock file), `pnpm audit --prod` (UI), `govulncheck` (agent, posture agent, provider) and Trivy
(`fs` with secrets, misconfiguration and vulnerabilities). No live system was attacked, and the lab was not touched.

Severity: **High** (cross-tenant, credential or whole-platform exposure), **Medium**, **Low**, **Info**.

## Summary

**Nothing critical.** No cross-tenant read of data, no authentication bypass, no injection into a rendered configuration and no secret
in the repository, the database or the logs was found.

3 Medium findings in code and 3 Low findings are fixed here, with tests. One High finding in the production deployment recipe
(unauthenticated etcd and Patroni) is **deferred**: it needs a tested change to a live HA cluster and belongs with the Operations work.

| Area | Result |
| --- | --- |
| Authn/authz and RBAC on every route | Sound. Every route is classified; `tests/integration/test_permission_matrix.py` fails the build for a route without a classification (ADR 0030). |
| Tenant isolation | Sound. `test_rls.py` asserts that every table with `tenant_id` has forced RLS and a policy; the app role has no `BYPASSRLS`. See R2 for one naming collision. |
| Sessions, cookies, CSRF | Sound. `HttpOnly`, `SameSite=Strict`, CSRF header on cookie writes, random 256-bit values. See D5. |
| Grafana proxy | One Low bypass of the deny list (R4). Credentials, `X-WEBAUTH-*` and forwarding headers are stripped; the data-source token is an HMAC, compared in constant time; queries are scoped to the tenant. |
| Secrets (OpenBao references) | Sound. No secret in logs (logging calls searched for secret material), fixtures or the repository (Trivy secret scan: none). |
| Config injection (HAProxy, FRR, Keepalived) | Sound. Validators refuse instead of escaping; the new WAF, CAPTCHA, broker and auth renderers go through `render.escape`. There is no dnsdist in this repository. |
| SSRF | Webhooks are pinned to the address that was checked. DNS, Kubernetes and JWKS endpoints have a weaker check (R5, D3). |
| Agent mTLS and bundle signing | Signing, engine binding and sequence numbers are sound. One impersonation path through the engine name (R1). |
| Packet capture and device posture | Sound. Capture builds the filter from typed fields, runs `tcpdump` without a shell, and bounds time, packets and bytes. Device reports are Ed25519-signed with a rising timestamp. See R2. |
| Container, LXC, Helm hardening | Controller image and Helm workloads are hardened; the proxy image is not (D2). LXC stays off by default (S4 of the earlier review). |
| Dependencies | pip-audit and pnpm audit: clean. Go: 13 standard-library and 7 module advisories in all three Go modules, fixed (R3). |
| CI secrets | No secrets in `.gitlab-ci.yml`; the job token is used only to upload SBOMs. CI had no vulnerability scan (R7). |

## Fixed in this review

Tests are in `controller/tests/unit/test_security_review_2026_10_13.py` unless stated. ADR 0210 records the decisions.

| # | Sev | Finding | Where | Fix |
| --- | --- | --- | --- | --- |
| R1 | Medium | **A tenant could name an engine like the controller.** The engine name becomes the CN and DNS SAN of its certificate, and `sy-agent -controller-cn` accepts a caller whose CN *or DNS SAN* matches. An engine called `switchyard-controller` (the default) enrolled and, whenever the PKI role also sets `clientAuth` (OpenBao's default is `client_flag=true`), could call `GetStatus` and `ProbeMember` on every agent of every tenant that it can reach. Bundles stay safe: they are signed. | `services/enrollment.py:182` | Enrollment refuses reserved names (`switchyard-controller` and `SWITCHYARD_CONTROLLER_CN`). The `agents` role in the quickstart and Helm bootstrap scripts gets `client_flag=false`; existing installations should run the same `bao write`. Test: `tests/integration/test_enrollment.py::test_an_engine_named_like_the_controller_gets_no_certificate`. |
| R2 | Medium | **PKI role ownership by prefix.** A posture policy's `pki_role` must start with `<tenant>-`, but tenants `acme` and `acme-corp` both match `acme-corp-devices`. Tenant `acme` could name `acme-corp-devices` and have its devices signed by the role (and CA) that `acme-corp`'s ports trust. OpenBao's `allowed_uri_sans` would normally refuse it, but the platform relied on a convention it did not enforce. | `domain/snapshot.py:563`, `services/devices.py:382` | The longest tenant name owns a role (`pki_role_owner`); the snapshot validator (`pki_role_not_allowed`) and the device service refuse the rest. Test: `tests/integration/test_devices.py::test_a_role_that_belongs_to_a_longer_tenant_name_signs_nothing`. |
| R3 | Medium | **Go advisories.** `govulncheck` reported 13 standard-library advisories (`net/http`, `crypto/tls`, `net/url`, `encoding/asn1`, `mime/multipart`) reachable from the agent and posture agent (enrollment uses `http.Client.Do` and `x509.CreateCertificateRequest`), `golang.org/x/net` 0.57.0 (fixed in 0.60.0) and, in the provider, `google.golang.org/grpc` (several, last fixed in 1.83.2) and `x/text`. | `agent/go.mod`, `posture-agent/go.mod`, `provider/go.mod` | `go 1.26.9`, `x/net` 0.60.0, `grpc` 1.83.2, `x/text`/`x/sys` current. `govulncheck` is clean in all three modules; Go tests pass. |
| R4 | Low | **The Grafana deny list could be skipped with `%3F`.** The path is decoded before the proxy sees it, so `api/users%3F` arrived as `api/users?`, which is not equal to `api/users` or under `api/users/`, and Grafana read it as `/api/users` with an empty query. The proxy session is a Grafana *Viewer*, so Grafana's own RBAC still refused the sensitive endpoints; this removes the second line of defence being silently absent. | `api/grafana_proxy.py:80-102` | Paths with `?`, `#`, `;`, backslashes, control characters, dot segments or empty segments are refused, and the deny list ignores case. |
| R5 | Low | **Shared address space was allowed as an endpoint.** `check_endpoint` (DNS providers, Kubernetes clusters, JWKS sync) refused loopback, link-local and RFC 1918 unless allow-listed, but `100.64.0.0/10` is neither "private" nor "global", so it passed. Some clouds put their metadata service there (`100.100.100.200`). | `adapters/dns/base.py:349` | Anything that is not globally routable needs the operator's CIDR list. IPv4-mapped IPv6 literals were already handled and are now tested. |
| R6 | Low | **`METRICS_TOKEN=change-me` was accepted.** `deploy/prod/node.env.example` ships the placeholder; the controller started with it. The token opens `/metrics` and the service-discovery list (management addresses, tenant names). | `runtime.py:536`, `cli.py` | Startup stops for a placeholder or a token under 16 characters. |
| R7 | Info | **No vulnerability scanning in CI.** | `.gitlab-ci.yml` | `audit-python`, `audit-go`, `audit-ui` jobs, `allow_failure: true` so a new advisory warns without blocking unrelated merges. Make them blocking once a run on main is green. |

Also fixed because it blocked the Go tests, not a security issue: `provider/internal/gen` did not write the SPDX header that the header-only
commit added to `zz_generated.go`, so `TestTheGeneratedTableIsCurrent` failed. The generator now writes it.

## Open findings (deferred)

| # | Sev | Finding | Where | Recommendation |
| --- | --- | --- | --- | --- |
| D1 | **High** (deployment) | **The production database stack is unauthenticated and unencrypted on the network.** etcd (Patroni's DCS) listens on `http://${NODE_IP}:2379` with no authentication or TLS; the Patroni REST API listens on `0.0.0.0:8008` with no authentication (its write endpoints change the cluster configuration, which Patroni applies to PostgreSQL, including `archive_command`: code execution as `postgres`); `pg_hba` admits `0.0.0.0/0` for `host` (non-TLS) connections. Anyone who can reach the three controller VMs on those ports can take over the database, and with it the desired state of every tenant. Mitigated only by the network firewall that the runbook assumes. | `deploy/prod/compose.yaml:78`, `deploy/prod/patroni/patroni.yml:5-6,32-33` | etcd with client-certificate TLS and authentication; Patroni `restapi` with TLS and basic authentication (`PATRONI_RESTAPI_USERNAME/PASSWORD`, and `ctl` settings); `hostssl` lines limited to the three node addresses. Needs a rehearsal on the HA lab (`deploy/prod/lab-drill.sh`), so it is not changed blind here. Until then document the firewall rule (2379, 2380, 8008, 5432 from the three nodes only) in the runbook. |
| D2 | Medium | **The proxy container runs as root and is not constrained.** `deploy/proxy/Dockerfile` ends on `nginx:1.27-alpine` without `USER`; `proxy-deployment.yaml` sets no `securityContext` (the API, worker and migrate job do). Helm values default the images to `tag: latest`; there is no `NetworkPolicy` and the pods keep a service-account token. Trivy: DS-0002 on this and the two test Dockerfiles, KSV-0014 on the OpenBao test manifest. | `deploy/proxy/Dockerfile:11`, `deploy/helm/switchyard/templates/proxy-deployment.yaml`, `deploy/helm/switchyard/values.yaml:8-9` | Move to `nginxinc/nginx-unprivileged` (port 8080 already), set `allowPrivilegeEscalation: false`, drop capabilities, pin image tags by digest, add a `NetworkPolicy` that admits only the proxy to the API and the API to the database, and `automountServiceAccountToken: false`. Not changed here because it needs a cluster run (`deploy/helm/test.sh`). |
| D3 | Low | **DNS rebinding between check and use.** `check_endpoint` resolves the host, then `httpx` resolves it again when connecting (PowerDNS, Kubernetes, JWKS). The webhook notifier already pins the checked address. | `adapters/dns/base.py`, `adapters/notify.py` (`_pin`) | Reuse the pinning transport of `HttpNotifier._pin`. The reachable targets are limited to what the first lookup allowed plus a name the tenant controls, so this needs a hostile authoritative server. |
| D4 | Low | **nginx trusts `X-Forwarded-For` from any private address.** An internal host can pick the client address the login rate limit sees. | `deploy/proxy/nginx.conf:12-14` | Trust only the SE group's addresses. |
| D5 | Low | **Session cookie is not `__Host-` prefixed and `Secure` depends on `SWITCHYARD_PUBLIC_URL`** (O8 of the earlier review). | `api/app.py:1550`, `422` | Rename the cookie `__Host-sy_session` once all deployments are https, and refuse to start in production without a `https` public URL. |
| D6 | Info | **Route 53 responses are parsed with `xml.etree`**, which expands entities. The source is AWS over TLS. | `adapters/dns/route53.py:17` | Use `defusedxml`. |
| D7 | Info | **CI images and runner.** `registry.gitlab.com/gitlab-org/release-cli:latest` is unpinned; the test jobs use `docker:27-dind` with TLS off on privileged pods. | `.gitlab-ci.yml:255`, `:53` | Pin by digest; keep the dind runners off shared infrastructure. |
| D8 | Info | **Client-chosen `X-Request-ID` is echoed and logged without a length limit.** | `api/app.py:1467` | Cap at 64 characters of `[A-Za-z0-9-]`, else generate. |
| D9 | Info | **Lab and dev defaults** (`devroot`, `lab-root-password`, `lab-superuser`, `POSTGRES_PASSWORD: postgres`) are labelled as lab-only and bound to lab networks. The e2e scripts under `deploy/lab/` belong to the Operations work and were not edited (they also still create the `agents` role without `client_flag=false`). | `deploy/lab/`, `deploy/dev/compose.yaml:8` | Apply R1's `client_flag=false` there when the lab is next rebuilt. |

## Not covered

- **The release feed and upgrade flow** (!143) is not on `main`; review it with that merge request.
- **The lab**: no probing or changes (Operations is redeploying it).
- **The built images**: Trivy scanned the repository (lock files, Dockerfiles, manifests), not images; scan the controller, proxy and SE
  images in CI once `audit-*` is blocking.
- **ACME and Cloudflare adapters** were read only for URL handling (trusted, system-administrator configuration, O9 of the earlier review).
- **OpenBao, Patroni and etcd settings in a running site**, the reverse proxy and TLS in front of the API, and a dynamic test of a
  running stack.
- **Posture agent on the laptop** beyond dependencies: its facts are the device's own claim, as the design says.
