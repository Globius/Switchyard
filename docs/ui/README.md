# Switchyard UI

The web UI lives in `ui/` (React 19, TypeScript strict, Vite, Tailwind v4, TanStack Query). See
`docs/design/03-frontend-design.md` for the design and `04-frontend-scope.md` for per-screen scope.

**Status:** scaffold, typed client, session plumbing and theme are in; screens are being built in
small MRs from the design handoff (`docs/design/ui-handoff/README.md`).

## Commands

Run from the repo root (Node 22+, pnpm):

| Make target | What it does |
| --- | --- |
| `make ui-install` | `pnpm install --frozen-lockfile` |
| `make ui-lint` | ESLint and Prettier check |
| `make ui-typecheck` | `tsc --noEmit` |
| `make ui-test` | Vitest with coverage (80% floor on `src/lib` and `src/auth`) |
| `make ui-build` | Typecheck and production build to `ui/dist` |
| `make ui-gen-api` | Regenerate `ui/src/api/schema.d.ts` from `docs/api/openapi.json` |
| `make ui-check` | All of the above plus a check that the generated client is current |

`pnpm dev` (in `ui/`) proxies `/api` to `SY_API` (default `http://localhost:8000`). Until the login screen
exists, put `SY_API=...` and `SY_DEV_TOKEN=<system-admin token from syctl token>` in `ui/.env.local`
(git-ignored); the dev proxy then sends the token as a bearer header. Dev only.

## Typed client

`ui/src/api/schema.d.ts` is generated by `openapi-typescript` from `docs/api/openapi.json` and
committed. After the controller's OpenAPI changes, run `make ui-gen-api` and commit the result;
`pnpm gen:api:check` fails if it differs. `ui/src/api/client.ts` wraps it with `openapi-fetch`.
TypeScript is pinned to 5.9 because `openapi-typescript` needs the JS compiler API.

## Auth and permissions

- The session is an HttpOnly cookie set by the backend; the SPA never holds a token.
- `useMe()` calls `GET /me` and stores `csrf_token`; the client sends it as `X-CSRF-Token` on every
  non-GET request. A 401 with problem `code: session_expired` calls the handler registered with
  `setSessionExpiredHandler` (the future re-login modal).
- `useProviders()` reads `GET /auth/providers`; `loginUrl(id)` is a full-page redirect;
  `useBreakGlassLogin()` and `useLogout()` cover the rest.
- `useCan(tenantId)` returns `can(verb, object)` giving `{allowed, required, reason}`. It reads the
  matrix from `GET /permissions` and the caller's role from `/me`; nothing is hard-coded. `reason`
  is the permission's description plus the needed role, for the tooltip on a disabled control.
- `POST /auth/refresh` is "Refresh access" in the user menu.

## Shell

`src/features/shell/` holds the top bar, nav, TenantSwitcher, command palette (`GET /search`),
user menu and ChangeSetBar. Routes are file-based (`src/routes`, generated `routeTree.gen.ts` is
committed). Screens that are not built yet render a `NotBuilt` placeholder. Review and the create
wizard sit outside the shell (full screen), as in the design handoff.

## Built

Every artboard of Design's v46 handoff has a screen:

- Tenant: home, virtual services (list, page with Overview / Settings / Rendered config / History,
  create wizard), pools, health monitors, certificates (PEM files or PKCS#12, issue, replace, usage),
  policies, networks and VIP pools, SE groups (engines, deploy, register), routing profiles, change
  sets, revisions with compare and rollback, jobs, review and apply (objects, config, impact,
  approval, conflict resolution, job progress), access and settings (members, role mappings, API
  tokens, approval and quotas).
- Admin (`/admin`, system-admin only): tenants, users, identity providers with break-glass, role
  mappings, system tokens, audit log.
- Login and the shell.

- The open draft is the change set whose `author` equals `principal` from `GET /me`.
- Every edit is an op in that draft; reads pass `?change_set=` so lists show your draft.
- Engine actions, tenant and admin settings act immediately (marked Live) and are audited; they do
  not go through a change set.

## Known differences from the design

- Revision "message" is read-only: the apply endpoint takes no message.
- Config diff is plain text, not Monaco.
- No per-member health on the Overview, and no "last check" column for failing members on Home
  (the API has neither).
- SE groups have no Placement card (no API for the Proxmox host layout); routing mode and networks
  are read-only in the group's settings.
- Tenant access shows quota limits only (no usage counts); the admin role matrix lists every server
  permission instead of the artboard's eight grouped rows.
- Audit log Export covers the events already loaded.
- Viewer (read-only) states are covered by tests only; no viewer user exists in the demo data.
- Theme: `ui/src/globals.css` from the design handoff (ADR 0042).
